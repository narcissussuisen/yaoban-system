## 3. Gate②前视审计 —— 核心纪律守住，但发现 1 处真实前视路径 + 2 处决策口径问题

### 3.1 守住的（复算通过）
三引擎（`detect_b_point` / `detect_dibu_buy(realtime=True)` / `detect_pullback_buy`）逐bar只用 **≤当前bar** 数据：

- **VWAP 为当日累计口径**（`vwap_series` 用 cumsum，bar i 只累加到 i），无未来 bar 泄漏。
- **放量拉升/白线向上/站稳** 用 `rolling(lb).mean().shift(1)`、`rolling(lb).min().shift(1)`、`rolling(surge_win).max().shift(1)`——全部**只看历史**，shift(1) 天然规避当前 bar 之后的窗口混入。
- `detect_dibu_buy` ①② 用 `rec.idxmax()`/`go.idxmax()`（**首个**满足 bar，顺序判定），③ 当 `realtime=True` 用 `up_to=df.iloc[:i+1]` 的累计成交额按 240/(i+1) 外推——只用 14:30 时点前数据，正确。④ 锁存式否决逐bar增量，无追溯。
- `detect_pullback_buy` 为顺序状态机（0→1→2→fire），每步只看当前 bar close/low 与累计 vwap。
- `prev_close` 读 F 盘日线 parquet 且 `df['date'] < day`（严格早于当日），**不含当日**，无同日收盘泄漏。

→ **「三引擎只用 ≤当前bar」申报属实。这是阶段一最重要的纪律，确认守住。**

### 3.2 发现的前视/口径问题（需整改）

**P1-3 【真实决策时点前视】`broke` 整 df 否决，未对齐触发时刻**
`scan_and_confirm.py` L182：
```
broke = bool((df['close'] < vw * 0.997).any())
if broke: ... 否决
```
- `df` = 当前拉到的**全部当日 1m bar（到当下）**，`broke` 对整 df 做「是否任何一根跌破均价线」判定，再去否决**极早触发候选**（`t = sorted(cands,key=ts)[0]` 取的是**最早**触发点）。
- **语义错位**：买点在 09:45，但否决用的是「到当下为止是否破过线」。在 2 分钟实时循环里，这等价于用**触发后 1~2 根**的走势否决（轻微前视）；在 `--force`/延迟重放里，等价于用**触发后整个下午**的走势否决（严重前视）。
- **修复方向**：`broke` 只对 `df.loc[:t]`（≤触发时刻）判定；或在触发 bar 当根即时判定，不做全 df `any()`。

**P1-2 【已验证据被违背】B1 未禁用**
`scan_and_confirm` L169 调用 `detect_b_point(df, prev_close=pc, max_pct=0.03)`，但 `detect_b_point` 默认同时产出 **B1（开盘强势）与 B2（回踩确认）**，且调用处**未禁用 B1**。
- 既有验证（GAP_intraday_mode L83/L111）：`B1 开盘强势 -0.33%（44%）负贡献需收紧`，`维持 B1 禁用、仅 B2 回踩确认`。
- 当前代码可触发 B1 → **违背已验证引擎契约**，把已验证的负贡献信号重新引入盘中建仓。
- **修复方向**：给 `detect_b_point` 增加 `allow_b1=False` 开关（或 scan_and_confirm 只取 B2），使盘中建仓严格对齐「H7.2 B2-only 正期望」口径。

**P1-4 【执行真实性】建仓价=历史触发bar收盘价，可滞后至 cooldown 上限**
`triggered` 存 `px`=触发 bar 收盘；`--execute` 用 `tg['px']` 记账（L198）。`sorted(cands,key=ts)[0]` 取**最早**触发（冷却 30min 内不重复）。
- 若最早触发在 30min 前，则**以 30min 前的价格成交**，而非当下市价 → 低估追价/高估吃价，回测与实盘失真。
- **修复方向**：以触发为**信号**，成交价取**当下**最新价（最新 tick 或最新 bar close），另计滑点；触发时刻仅用于记录规则。

**3.3 非前视、但值得注意**
- `pull_minutes` 要求当日 ≥5 根，否则返回 None → 开盘前 4 分钟（09:35-09:39）无法确认，首个可确认点 ~09:39。可接受，但「开盘强势」B1 本就主要落在前 30min，若未来收紧窗口需注意此边界。
- 异动池按 `-chg` 排序取 Top20，确认仅 `pool[:8]`（L161）→ **候选 9-20 本轮永不确认**。这是吞吐/覆盖设计（自验已标「每轮最多确认8只」），非前视，但与「选手实际买入不一定是当日涨幅最高的前 8」存在错配，建议评估打分/采样而非「涨幅 top8」。

**Gate② 裁定：核心无前视（三引擎逐bar纪律守住），但 P1-3 是必须修复的真实决策时点前视；P1-2、P1-4 为工程口径问题，一并列入整改。**

## 4. Gate③ tick_monitor 守护逻辑 —— 部分通过，限频长期风险未闭环（本评审最高风险项）

### 4.1 时段/休眠/退出逻辑（复算通过）
- 常态（--daemon）：`09:35≤hm≤11:30` 或 `13:05≤hm≤15:00` 才轮询；否则 `hm>15:05` 则 `break` 退出，否则 `sleep(60)` 继续等待。→ **09:31-09:35 休眠、午休 11:30-13:05 休眠、15:00 后休眠至 15:05 退出**，符合申报「09:35-11:30/13:05-15:00 轮询、15:05 退出」。
- 触发去重用 `fired={ (sym,type) }`（L79），同一触发当日只执行一次，**避免反复触发**——正确。
- 触发分类正确：止损（全出）、炸板（全出）、破均价线减半（半出）、做T观察（提示级不自动）。**做T 保持提示级**，与自验「差价确认规则待选手案例校准后自动化」一致，稳妥。

### 4.2 限频/失效风险（本评审重点，需整改）

**P1-1【最高风险】秒级监控长期限频风险未被压力测试确证**
- `stress_tdx_tick.py` 复算发现：它测的是**延迟**（P50/P95），不是**限频边界**。240 次请求、峰值约 **1 req/s**（1s 间隔 × 2 标的 × 30 次，两标的前后串行不并发），持续时间极短。
- 而守护模式实际负载：**每个持仓每 3s 做 2 次调用**（`get_security_bars(300)` + `get_transaction_data(30)`，L102/L122）。P=2 → ~1.3 req/s；P=5 → ~3.3 req/s；3.5h 满盘即 **1.7万~4.2万次/日**。
- **压力测试与守护全天负载完全不同量级**：「1s 零失败/P50 67ms」只是**低速率、短时、测延迟**的结论，**不能外推为「全天 3s 轮询不会封 IP/被限频」**。
- 我复算探针（2 标的 × 8 次 @1s，n=16）：`P50=73ms、P95=1030ms、max=1030ms`（申报 P95≈400ms）。**P95 明显受长尾抖动影响可达 ~1s**——一次近 1s 的请求在 3s 轮询里尚可吸收，但若逼近连接超时（8s）会卡循环；限频时请求可能返回空/慢，守护会**静默降级**。
- **降级方案（建议直接落地）**：
  1. **自适应间隔**：检测到失败/空返回/长延迟（如 >500ms 连续 3 次）→ 间隔 3s→5s→10s，逐级退避并告警。
  2. **滚动错误率熔断**：维护最近 N 次请求的错误率，超过阈值（如 >10%）→ 降级为「仅 1m bar 轮询 + 现价兜底」，并写告警到 `outputs/intraday/live_alerts.json`。
  3. **请求预算**：每持仓每分钟的调用次数设上限；优先保障**止损/炸板**这类「秒级必须」的判定，其余（做T观察）降为分钟级。
  4. **分源**：持仓多时分摊到多服务器/备用源；对高频逐笔需求用更轻接口。
  5. **基线间隔回调到 5s**：路线图 §1.1 为「每 5 秒」，代码默认 3s 是超路线图收紧；在限频未确证前先 5s 更稳。

**P1-1b【失效回退缺失】循环内无重连/无主备切换**
- `tick_monitor` 只在**启动**时对 2 服务器做一次连接；若盘中连接断开或主服务器开始限频，`get_*` 抛异常被 except 吞掉，`tick_px`/`bars` 回退为 **逐笔 vs 1m bar 的兜底**（L104/L125），**之后整个下午静默用分钟级陈旧价**，且**从不重连、不切到备服务器**。
- 「秒级盯持仓」在连接退化时**静默失效**，无任何告警。这是守护可用性的真实缺陷。
- **修复**：循环内检测连接/请求失败，超过阈值即重连（含备服务器 failover），重连失败则退出并告警（而不是无限静默降级）。

### 4.3 其它
- `save(st)` 每 3s 重写整个 `ledger.json`（indent=1），+`pos_live.json` 每 3s。随着 fills 增长文件变大，3s 全量写偏重；建议 ledger 写入节流（如仅触发/收盘写，或增量写）。
- `fired` set 在循环外创建，**跨日不重置**。当前每日任务 09:31 起跑（6h 上限至 ~15:31）不会跨日，故暂无害；但若改为常驻/跨午夜，fired 需按日清空（防御性）。

**Gate③ 裁定：条件性通过。** 时段/休眠/退出/去重正确；**限频长期风险与无重连失效回退未闭环，为本评审最高级整改项（P1-1/P1-1b）。建议在 1 个完整交易日灰度 + 上述降级方案落地前，不宜长期无人值守运行。**

### 5.2 需校准 / 自相矛盾的部分

**P2-1a【注释与代码矛盾】涨幅窗口**
- 注释 L86 宣称「低吸口径 0~5%，强势口径 5~9.8%」为两档，但代码 L87 仅 `if not (-1 <= chg <= 9.8): return None`——**单一窗口，未分档**。
- **更关键**：引擎端 `detect_b_point(max_pct=0.03)` 与 `detect_pullback_buy(max_pct=3.0)` 都把**触发时刻涨幅**卡在 ≤3%；因此**实际买点涨幅窗口是 ≤3%**，而非注释所称「5~9.8% 强势口径」。➡ **9.8% 的预筛上界与引擎 ≤3% 触发上界自相矛盾**（预筛放行 5-9.8% 的票，引擎却几乎不可能在其 5-9.8% 时触发，因为触发要求 ≤3%）。「强势口径」被声明但未实现。
- **校准方向**：要么把预筛上界与引擎对齐（如收窄到 ~5%，或明确「低吸≤3% / 强势≤7%」并把引擎强势档真正启用——需要选手证据支撑 7% 触发胜率），要么删除误导性注释。建议：**先按证据启用「≤3% 低吸」单口径**，强势档单独回测后再开放。

**P2-1b【阈值无选手证据】换手 3-30% / 额≥1亿**
- 选手锚库 `PLAYER_TRADES_ANCHOR.md` 有 70+ 笔（日期/代码/价格/战法/结果），**但无换手、成交额列** → 这两个阈值**无法从锚库直接校准**，属「经验初值」。

- **校准方向**：① 若 F 盘有 1m/日线数据 + 选手买入点，可回填选手每笔买点的**当日换手/成交额**分布，取「覆盖多数买点」的窗口；② 或对 2025-2026 全市场异动池的「后续走强」样本做**区分度**分析（这些阈值能否把「触发后走强」与「冲高回落」分开），用 AUC/覆盖率定窗；③ 至少先对「换手 3-30%」做个敏感性检验（扩到 2-40% / 收窄到 5-20%）看触发池与胜率变化。

**P2-1c【范式错配提示】**
- 选手模式是「**盘后选观察池→次日盘中 B 点确认**」（GAP_intraday_mode §1），而非「全市场盘中异动扫描」（roadmap §1.2 是扩展/推广）。因此 `rough_screen` 是**替代「日线观察池」的粗筛器**。它的阈值要能回答「哪种**当日异动**股票值得盘中确认」，与选手「观察池形态」是不同对象——**阈值校准必须落到「当日异动→触发→次日/当日走强」的实证上**，而非选手模式日线池。

**Gate④ 裁定：条件性通过。** 额≥1亿/ST/一字剔除合理；**换手与涨幅窗口为经验初值、且涨幅窗口注释/代码/引擎三者自相矛盾，需按 P2-1 校准后再作为建仓防线。** 建议粗筛先**降级为「提示/半自动」**，待阈值校准后再用于自主建仓。

## 6. Gate⑤自主执行风险 —— 条件性通过，资金边界需补强

### 6.1 已守住的部分
- **单票≤30%**：`alloc=100000*0.9/3=30000`（30% 本金，注意非当前权益），`triggered[:2]` 每轮最多 2 只。**单票 30%、轮次 2 只**与申报一致。
- **最低 100 股**：`qty=int(alloc/px//100*100)`，不足 100 股跳过（防碎股）。
- **资金硬校验**：`ledger.buy` 检查 `cost > cash` 则拒绝（L46），不至于超现金。
- **默认止损 5%**：`buy(stop_pct=5.0)` 设 `stop_px=px*0.95`，台账层面有止损字段，tick_monitor 可读取。
- **做T 保持提示级**：未自动执行，避免无差价确认规则的自动高抛低吸（自验 §4 一致）。

### 6.2 风险敞口 / 边界不足
**P2-2【仓位是固定本金 30%，非当前权益 30%】**
- `alloc` 用**初始 10 万**而非当前权益/净值。权益增长后 30% 初始本金 < 30% 当前权益（**系统性欠配**）；权益回撤后 30% 初始本金 > 30% 当前权益（**风险放大**——某阶段可能单票超当前权益 30% 的「单票≤30%」承诺）。
- **修复**：`alloc = 当前权益 × max_pos_pct / 槽位数`，并做最大持仓数硬上限。

**P2-2b【无账户级总敞口上限，靠现金隐式约束】**
- 全市场扫描每 2min 一轮，只受 `cash` 约束 → 当天可反复买入；tick_monitor 部分卖出释放现金后又可再买 → 可能日内多次轮换、敞口波动。
- **修复**：账户级**最大同时持仓数 / 最大毛敞口**硬上限（如 ≤3 只、毛敞口 ≤90%），且「买入总次数/日」设上限，避免过度交易（选手模式是低频精选，非高频轮动）。

**P2-3【同日落单无当日止损保护——真实风险边界缺口】**
- `buy` 设 `stop_px`，但 `ledger.sell` 强制 T+1（当日买入不可卖，L68-70）。因此 **scan_and_confirm 当日买入的持仓，tick_monitor 的止损/炸板/破线在当日全部被 `T+1 违规` 拦截**（sell 抛 ValueError → 被 except 吞掉打印「止损失败」）。
- 含义：**当日盘中的自主买入，在 T+1 约束下当天没有任何下行保护（不能止损），只能押到次日**。若盘中买入后跳水，当日无法离场，裸持隔夜风险。这是中国市场真实规则，但作为「自主执行」必须**显式识别并规避**：
  - 建议：**尾盘/临近收盘的自主买入禁用或缩减**（避免买入即裸持隔夜）；或对当日买入默认**更低仓位**、在下一交易日开盘即按 stop 处理；并在日志/台账**显式标注「当日买入：T+1 止损失效至次日」**，而非静默吞掉异常。

### 6.3 其它
- **炸板全出较激进**：tick_monitor `elif` 炸板（L140）触发即**全出**（非减半分批）。符合选手「封板不坚决=落袋」（v50/v55 清仓口径），但全出对单次异常 tick 敏感。
- **止损单 tick 确认**：止损用 `get_transaction_data` 最新一笔价（L123），单笔异常价可能触发误止损。建议止损用 **2 笔连续低于 stop**（或「最新价 + 最新 bar 收盘双确认」）再执行，减少单笔闪价误杀。

**Gate⑤ 裁定：条件性通过。** 单票 30%/轮次 2 只/默认 5% 止损已守住；但**「固定初始本金百分比」、「无账户级敞口上限」、「当日 T+1 止损失效」三处资金边界需补强（P2-2/P2-2b/P2-3）**，且建仓价用历史触发bar价（P1-4）会低估真实成交价。

## R2. P1-1 自适应/熔断详析（为何是死代码）

1. **自适应间隔未应用**：L83 `interval = args.interval`；L144 `interval = min(interval*2, 30)`（错误时）；但 L223 `time.sleep(args.interval)`——**sleep 用的是原始 `args.interval`，适配后的 `interval` 从未用于控制轮询**。即使用户灰度传 `--interval 5`，自适应（5→10→20→30）也不会真正放慢轮询。

5. **`break` 语义**：L137 `break` 在**第一遍 for 循环**内，只跳出第一遍，不跳出 `while`——「连接失效且重连失败——本轮跳过」打印后，仍会继续进入第二遍（真实拉取）。「本轮跳过」并未真正跳过本轮。
