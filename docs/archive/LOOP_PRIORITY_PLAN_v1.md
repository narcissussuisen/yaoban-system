> 样本外验证 → 评审 → 合入/归档），按五维打分：证据强度 / 数据可得性 / 实现成本 /

## 一、优先级排序（P0-P3）

### P0-A：动量池/回踩池 2023-2024 复验
- 内容：backtest_market.py + pullback 研究在 2023/2024 重跑（数据已齐：F 盘 2003-2026）
- 依据：现有两池仅 2025/2026 两年证据；5+ 打板已复验 4 年（2024 最弱）——两池必须同标准
- 五维：证据强度 中高（已有 2 年正）｜数据 就绪｜成本 低（脚本已建）｜正交 直接强化基线｜失败成本 低
- 通过标准：两年均正期望 + t≥1.96（按 R1 评审建议）；胜率按用户决策口径（低胜率可接受）
- 产出：outputs/backtest_market_2023/2024.md + 审计表

### P0-B：同日择股系统化（替代随机）
- 内容：raw CSV 已含连板数/封板等列 → 排序规则（连板数、封板时间、市值、板块位置）
  → 组合级回测对比"随机选取"（2025 已证随机稀释期望 +1.60% vs 信号级 +2.26%）
- 依据：评审发现"同日随机取"系统性稀释期望，存在规则化空间
- 通过标准：规则化择股 ≥ 随机基线 + 统计显著；两年独立验证
- 产出：outputs/selection_alpha_{year}.md

### P0-C：冰点期空仓开关（regime 开关）
- 内容：炸板率>35 或 涨停家数<25 → 空仓/半仓；组合级回测（单吊与双票各一版）
- 依据：2025-10 单月 -41% 是最大回撤来源；分桶已见方向（2025 炸板率>35 空仓后胜率 51% vs 46%，但样本缩 80%——需组合级重估）
- 通过标准：开关开启后组合收益不降 + 最大回撤显著下降；两年独立验证
- 产出：outputs/regime_switch_{year}.md

### P0-D：4 板晋级失败特征
- 内容：4 板 2026 -0.88%（n=134）破坏单调性 → 研究 4 板晋级 5 板的条件（炸板次数、板块跟风、情绪）
- 依据：5+ 池阈值依据完善；可能发现"5+ 前一日 4 板的可买性"信号
- 通过标准：晋级特征有样本外区分度（分组均值差显著）
- 产出：outputs/promo4_findings.md

### P1-A：B 点恐慌衰竭低吸（L2 质量因子）
- 内容：R7 每日采集已就绪 → 积累 ≥1 个月 tick → L2 质量分 → B 点重定义（缩量企稳+抛压衰竭）
  → 全 L2 回测（l2_quality_score.py 扩展）
- 依据：三天 76 样本方向性证据（弱承接 +3.43%/79% vs 强承接 +1.82%/59%）
- 前置：tick 数据 ≥20 个交易日（预计 2026-09 末可启动论证）
- 通过标准：两年口径不可直接做（L2 仅 2026-08 起）——先做"当月样本外 + 与日线模式正交性"验证，通过后进入月度滚动论证
- 产出：outputs/l2_bsell_findings_v2.md

### P1-B：5+ 板内选优（L2 封板质量）
- 内容：首封时间/封单/流通市值比/撤单率 → 5+ 池内分层 → 可成交率与胜率提升
- 前置：同 P1-A（同一批 tick 数据）
- 通过标准：选优层在 5+ 池内均值差显著 + 可成交率提升
- 产出：outputs/l2_board_quality.md

### P2-A：做 T（日内高抛低吸）
- 内容：分钟级持仓模拟框架（src/core/sell.py T 引擎已有雏形）→ 小样 100 笔验证 T 贡献
- 依据：选手 6 倍收益重要来源；日线模拟完全缺失
- 前置：先建框架（工程量最大）→ 用 2025/2026 已有持仓样本做小样
- 通过标准：T 贡献 ≥0.3%/笔·日 且不显著放大回撤 → 进入全量模拟
- 产出：outputs/t_contribution.md

### P2-B：分时 B 点执行层（H7）

- 通过标准：B 点执行 vs 开盘执行 两年正差 + 胜率提升
- 产出：outputs/intraday_bpoint_{year}.md

### P3：滑点/阈值/卖出敏感性 + 板块-情绪交叉
- 内容：滑点 0.2/0.3% 敏感性、卖出变体、板块×情绪二维交叉
- 依据：稳健性检验项；单维已不稳健，二维大概率过拟合——仅作报告
- 通过标准：敏感性不翻转结论；交叉无显著二维效应则归档
- 产出：outputs/sensitivity_report.md

## 二、自动循环系统设计（loop engine v1）

### 目标
系统自主：状态登记 → 任务生成 → 执行 → 验证 → 评审 → 迭代，替代人工逐条提示。

### 架构（四件套）
1. **状态文件** docs/loops/state.json（单一事实源）
   ```json
   {
     "modes": {
       "P0-A": {"status": "pending", "phase": "spec", "artifacts": [],
                 "gate": {"win_years": 2, "min_t": 1.96}, "next_action": "run_backtest_2023"},
       "P1-A": {"status": "waiting_data", "phase": "collect", "data_days_needed": 20,
                 "data_days_now": 3, "next_action": "wait"}
     }
   }
   ```
2. **任务生成器** scripts/loop_engine.py（每轮读 state.json → 输出待执行任务卡 tasks/next_task.json）
   - 规则：status=pending 且前置满足 → 生成任务卡；waiting_data → 检查数据量阈值 → 达标转 pending
3. **执行器**（本次会话内 = 我，按任务卡执行；回测脚本已有则直接跑，新研究则建脚本）
   - 每任务卡：{mode_id, action, cmd_或_研究问题, 通过标准, 输出文件}
4. **验证器 + 评审触发器** scripts/loop_validate.py
   - 自动断言：输出文件存在 + 通过标准满足（正期望/t/胜率/样本量）
   - 达标 → 状态转 review_ready → 触发量化专家 subagent 评审（docs/reviews/）
   - 不达标 → 状态转 failed/retry 并留档
   - 评审通过 → 转 baseline 并入 SYSTEM_OVERVIEW；有条件 → 生成整改任务卡

### 循环节奏
- 每日 16:35 定时跑 loop_engine.py（数据/状态检查 + 任务卡更新）
- 我在会话中消费任务卡执行；任务完成后跑验证器写回状态
- 月度：评审通过的模式自动进 R6 模拟盘跟踪

### 与现有资产的复用
- 回测框架：backtest_market.py / backtest_daban.py / pullback_b2_test.py / portfolio_sim.py
- 评审机制：docs/reviews/_TEMPLATE.md + subagent 评审（R2 机制已建）
- 调度：install_schedule.ps1 已注册 4 任务，加挂 YaobanLoopEngine（16:35）
